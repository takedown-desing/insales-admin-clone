01Задача

Оффер: «Хватит платить InSales 150–170 тысяч в год — перенесём ваш магазин на обычный хостинг за 48 тысяч, всё останется один в один, включая привычную админку». Окупаемость для клиента около четырёх месяцев.

Ближайший шаг — не построить это, а понять, как делать перенос повторяемо: один раз собрать процедуру, чтобы каждый следующий клиент занимал часы, а не недели, и чтобы ничего не терялось.

Задача распадается на четыре разные работы, которые легко перепутать между собой:

  1. Витрина — фронт сайта один в один, с сохранением SEO
  2. Данные — товары, категории, картинки, страницы, мета-теги
  3. Админка — упрощённая копия: товары, цены, фото, остатки
  4. Учётная система — синхронизация остатков с МойСклад

Метки стоят у каждого утверждения, которое влияет на оценку сроков. Разница между «работает» и «должно работать» здесь стоит недель.

02Как устроена админка

admin2 — одностраничное приложение на Vue. Готового HTML с формами оно не отдаёт: поля рисуются на клиенте, атрибутов name у них нет, только автогенерённые input-715. Настоящий контракт данных живёт в JSON-запросах между приложением и сервером.

Что из этого следует

Нашу админку можно делать на любом стеке. Клиент воспринимает расположение экранов, названия полей и порядок действий — не технологию под ними. Копировать надо интерфейс и логику, а не архитектуру InSales.

проверено живьём Официальный REST API /admin/*.json отвечает прямо по сессионной куке администратора, без API-ключа. Проверено на 22 эндпоинтах, включая полный цикл записи: создание товара вернуло 201, удаление — 200, каталог вернулся к нулю.

06Экраны к повтору

Карточка товара

Фото загрузкой файлом, название, описание в визуальном редакторе с кнопкой «Создать с AI», галка дополнительного описания, три ценовых поля, количество с плейсхолдером ∞, галка «Показывать», поиск по категориям, поиск по коллекциям.

Шапка с номером, датой и кнопками «Оформить доставку» и «Копировать». Три селекта: статус заказа, статус оплаты, способ оплаты. Таблица позиций:

Цены и остатки

Вкладки «Все / Цены / Остатки». Колонки: название, себестоимость, склад, цена продажи, скидка, цена до скидки, штрихкод. Фильтры по диапазонам для каждого числового поля, наличие фото, наличие остатка. Массовые изменения и акции с периодом действия.

Новый клиент

Имя, телефон, почта — обязательные. Подписка на новости, согласие на обработку персональных данных (обязательное), уведомления о заказе, населённый пункт (обязательный), индекс, улица, дом, квартира.

Страница и блог

У страницы: заголовок, пермалинк с префиксом домен/page/, редактор, SEO-поле, галка показа на сайте. У блога дополнительно: категория, настройки комментариев, уведомления, CAPTCHA, проверка на спам, запрет ссылок в комментариях, тег title и мета-описание.

07Каналы выгрузки магазина

Парсить каталог не нужно. С вёрсткой сложнее, чем казалось на старте.

Данные работает

Базовый URL https://{домен}/admin/{сущность}.json, Basic-аутентификация. Забираем products с вариантами и картинками, collections, categories, option_names, properties, orders, clients, pages, blogs, menus, fields, delivery_variants, payment_gateways, account.

Подводный камень с ключами

ограничение тарифа На пробном тарифе создать API-ключ не дают: экран «Ключи доступа» отвечает «Достигнут лимит активных ключей. Улучшите свой тарифный план или докупите опцию отдельно». У клиента доступ к API может оказаться платной опцией — проверять надо на входе, до обещаний по срокам.

Обходной путь, который сработал: все /admin/*.json отвечают по обычной сессионной куке администратора, без ключа вообще. Для разовой выгрузки при переносе этого достаточно, для постоянной интеграции — нет, сессия живёт недолго.

Исходники темы работает частично

GET /admin/themes.json                              → id темы, is_published
GET /admin/themes/{theme_id}/assets.json            → список файлов темы
GET /admin/themes/{theme_id}/assets/{asset_id}.json → поле content с исходником

Тема «Base» состоит из 24 файлов. Забрались 17 — все Liquid-шаблоны и сниппеты. Не забрались 7: .scss, .js, .png и четыре config/*.json — у них поля content нет, только ссылка на CDN, а нужный хост на магазине без домена пустой.

templates/   index · product · collection · cart · page · blog · article · search
             compare · favorite · shared_cart · page_404
             layouts.layout · layouts.checkout2 · layouts.client_account
snippets/    head · styles
config/      settings · setup · messages · settings_data
             theme.scss · theme.js · favicon.png

Почему «крутить их Liquid у себя» не сработает на новых темах

Главная находка. Шаблоны современной темы пустые — вся разметка вынесена в виджеты:

{% for widgetDrop in widget_lists.product-list.widgets %}
  {% widget widgetDrop %}
{% endfor %}

product.liquid весит 97 байт, index.liquid — 95. Определения виджетов наружу не отдаются: /admin/widgets.json, /admin/widget_lists.json и все варианты с идентификатором темы отвечают 404. Сверх того, в шаблонах сидят системные инклюды платформы — system_seo_description, system_v4_meta_data, system_microdata, — которых в исходниках темы тоже нет.

Два сценария, и на входе каждого клиента надо определить, какой

Старая кастомная тема. Разметка лежит прямо в Liquid-шаблонах. Исходники через Asset API дают почти готовую вёрстку, остаётся заменить теги на свои.

Новая виджетная тема, как «Base». Исходники дают только каркас layouts.layout и head со всей SEO-логикой. Саму разметку страниц придётся брать из отрендеренного HTML витрины и пересобирать — то есть ровно так, как предлагалось изначально.

Asset API при этом всё равно полезен: head.liquid показывает точную логику canonical и мета-тегов, layouts.layout даёт HTML-скелет, config/settings — параметры темы. Это не заменяет вёрстку, но избавляет от угадывания.

08Что не проверено

Честный список, чтобы на него не наткнуться в момент, когда сроки уже названы.

  • Бинарные ассеты темы — content через API не отдаётся, нужен CDN-хост, а на магазине без домена он пустой. Проверить на реальном клиенте.
  • Создание API-ключа на платном тарифе — на триале заблокировано лимитом.
  • Экран редактирования существующего товара /admin2/products/{id} редиректит на главную, реальный маршрут не найден.
  • Структура товара снята с созданного и тут же удалённого — в магазине не было ни одного товара.
  • Интеграция с МойСклад — не трогал, нужен их тестовый аккаунт.
  • Часть эндпоинтов admin2 отвечает 406 на сессии. Официальные аналоги /admin/* при этом работают, так что на дело не влияет.

09Открытый вопрос

Это вилка между «два дня на клиента» и «два месяца», и пока она не закрыта, любая оценка сроков держаться не будет.

Магазин — это не только витрина, каталог и админка. InSales из коробки даёт корзину, оформление заказа, эквайринг, доставку, онлайн-кассу с чеками по 54-ФЗ и письма покупателям. На главной странице их админки висит баннер «Эквайринг + онлайн-касса» — это ядро продукта, за него и платят.

Если продаём «один в один», всё это надо строить или подключать сторонними сервисами, и хостингом за 500 рублей дело не обойдётся. Если продаём витрину, каталог и заявки с уходом заказа в МойСклад или на почту — задача реалистична в заявленные сроки и деньги.

Второй вопрос, помельче

Тема магазина может быть платной — от InSales или стороннего разработчика. Товары и контент принадлежат клиенту, дизайн темы — нет. Практический выход: пересобирать вёрстку по исходникам, а не выкладывать их файлы как есть, либо смотреть лицензию конкретной темы.

Сырые материалы — 150 страниц, 137 скриншотов, дампы API и исходники темы — лежат в рабочей папке проекта. Сессия админки сохранена, повторный вход без СМС возможен до истечения пробного периода.
